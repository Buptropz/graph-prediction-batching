# SQL batching comparison
Recorded on 2026-11-24 before running either SQL plan. This is a database execution study on previously examined panels. Directional hypotheses use the earlier graph experiments.

For each of Cora and PubMed, use all five fixed panels of 24 focal papers and their two disjoint-from-focal counterpart requests of 32 papers, selected separately from the low and high ends of the existing feature ranking. Both requests share the same 48 labeled supports. Keep the input ID, feature, and edge relations fixed. Compare two DuckDB statements differing only in their grouping key before the identical prediction function. The split plan calls the function once per request. The pooled plan calls it once for both requests. The focal request is always first. Preserve row order and rescope node indices and edges to the chosen request. Return IDs and class probabilities for every row and evaluate membership in predicted-topic groups in SQL.

Use CPU, two PyTorch compute threads and one DuckDB execution thread, for both public checkpoints and both feature-normalization settings. Warm each plan once per case and measure three paired executions, alternating plan order with case and repetition. Record complete result vectors, group memberships, invocation counts, paired wall times and process peak RSS. Repetitions measure time only. Pool low and high exposures with an explicit denominator and also report distinct focal papers affected. Compare pooled focal probabilities to retained model outputs and split focal probabilities to the focal-only outputs. Require identical IDs, SQL-to-vector parity and maximum absolute probability discrepancy no greater than 0.000001 against those archives. If a required check fails, diagnose it before reporting.

Prediction: on each dataset at least one focal paper moves to another topic group under pooled evaluation for each jointly normalized model, while support-only NodePFN changes no focal memberships. One failed comparison suffices to refute universal invariance for that recipe. Report all settings and any contrary outcome. No directional win criterion for latency or support-only Ephris. This experiment measures explicit grouping in an embedded CPU engine; it does not test an optimizer's choice.
